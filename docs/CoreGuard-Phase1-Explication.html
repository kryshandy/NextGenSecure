Une suite de sécurité 100 % locale pour Windows 10/11 : aucun cloud, aucune donnée envoyée à l'extérieur. Chaque partie de ce document se lit à deux niveaux : en français facile, puis en termes informatiques.

1. En résumé

En français facile

CoreGuard est un garde du corps pour l'ordinateur. Il examine les fichiers pour repérer ceux qui sont dangereux, surveille ce qui se passe en permanence (programmes qui démarrent, scripts, clavier, fichiers importants) et réagit : il bloque, isole ou arrête le coupable.

Il a aussi une petite IA embarquée, qui explique en langage simple pourquoi un fichier est suspect. Mais ce n'est jamais elle qui décide de bloquer : ce sont des règles vérifiables.

En termes informatiques

  • .NET 10 (LTS), C#, WPF (MVVM, CommunityToolkit), solution modulaire : chaque module ne dépend que de AntivirusIA.Core.
  • Fonctionnement 100 % user-mode (Ring 3 + service LocalSystem) : le driver Rust Ring 0 est en pause, rebranchable via l'abstraction IKernelActionProvider.
  • IA locale : LLM Llama 3.2 3B quantifié (GGUF Q4_K_M) via LLamaSharp, cantonné à l'explication.

2. Architecture

CoreGuard est fait de trois composants qui se parlent, plus des « briques » spécialisées.

En français facile

L'interface est ce que tu vois. Le service est le « vigile » invisible qui tourne avec les pleins pouvoirs, même quand l'interface est fermée. Il est accompagné d'un chien de garde : si quelqu'un abat l'un, l'autre le relève. L'extension navigateur vérifie les pages web.

En termes informatiques

  • IPC UI ↔ service : NamedPipeServerStream, trames longueur + JSON (≤ 1 Mo), ACL : réseau refusé, utilisateurs interactifs en lecture/écriture.
  • Anti-usurpation : le client exige un serveur en session 0 (GetNamedPipeServerProcessId + ProcessIdToSessionId).
  • Canal limité : état, alertes, analyse AMSI, et arrêt authentifié. Aucune commande « tuer tel processus » n'est exposée.

3. Analyse d'un fichier : la logique du score

Quand un fichier est analysé (à la demande, ou automatiquement s'il arrive dans Téléchargements), il passe dans une chaîne de moteurs. Chacun ajoute des « indices » avec des points ; le total donne un score de 0 à 100.

En français facile

  • Si le fichier est déjà connu comme virus (son « empreinte digitale »), c'est 100 points d'emblée.
  • S'il contient des phrases typiques de logiciels malveillants (un outil de vol de mots de passe, une note de rançon…), il prend des points.
  • S'il a des allures louches (programme déguisé en PDF, code compressé pour se cacher…), il prend des points aussi.
  • S'il est signé numériquement par un éditeur reconnu, ses points « louches » sont divisés par 4. En revanche, une preuve certaine reste une preuve, même s'il est signé : des certificats peuvent être volés.

En termes informatiques

  • Indicator(Source, Description, Points, Definitive) : les indices définitifs (hash connu, règle caractéristique) ne sont jamais atténués.
  • PatternRuleEngine : chaînes ASCII / UTF-16, hex avec jokers ??, conditions any / all / N, sur les 32 premiers Mo. Les motifs sensibles sont stockés en hexadécimal dans rules.json.
  • PeStaticEngine : System.Reflection.PortableExecutable, entropie de Shannon par section, sections RWX, IAT pondérée (WriteProcessMemory, CreateRemoteThread…).
  • Échec sécurisé : un PE malformé ou un moteur qui plante ajoute des points au lieu de laisser passer.
  • WinVerifyTrust hors ligne : la signature valide divise les heuristiques par 4.
  • Quarantaine : AES-256-GCM par blocs de 1 Mo (en-tête, index et dernier bloc authentifiés), clé protégée par DPAPI, droits NTFS restreints (exécution refusée).

5. Réponse aux menaces et auto-défense

En français facile

Détecter ne suffit pas : il faut agir. CoreGuard peut arrêter un programme, le geler, lui couper Internet ou verrouiller un fichier. Il refuse toujours de toucher aux programmes vitaux de Windows, pour ne jamais provoquer d'écran bleu.

Un virus essaie souvent de tuer l'antivirus avant d'agir. Avec CoreGuard, « Fin de tâche » est refusé, l'arrêt du service par Windows est refusé, et si un des deux processus tombe, l'autre le relance. Seul ton mot de passe peut éteindre la protection.

En termes informatiques

  • IKernelActionProvider (Core) / UserModeActionProvider : TerminateProcess, NtSuspendProcess, blocage pare-feu, ACL NTFS, DACL de processus. Garde-fous : PID ≤ 4, liste critique, IsProcessCritical.
  • DACL : SYSTEM en accès complet, OWNER RIGHTS et Everyone limités à QUERY_LIMITED | SYNCHRONIZE.
  • Service : CanStop = false. Watchdog : signal d'arrêt légitime signé HMAC sur un stdin privé.
  • Arrêt : défi-réponse HMAC-SHA256, clé PBKDF2 (600 000 itérations), nonce à usage unique valable 60 s, verrouillage 5 min après 5 échecs. Le mot de passe ne transite jamais.

Verrouillage d'urgence du PC : comment il marche et comment on déverrouille

En français facile

Pour verrouiller : le bouton « Verrouiller le PC » du tableau de bord, ou automatiquement si une clé BadUSB est détectée, ou à distance depuis ton téléphone : tu déposes dans ton dossier OneDrive / Google Drive un petit fichier « CoreGuard-VERROUILLER.txt » qui contient ton code secret. Dès que le PC le reçoit, il se verrouille.

Ce qui se passe : Windows se verrouille ; derrière, un écran CoreGuard couvre tous les écrans. Le clavier ne sert plus qu'à taper le mot de passe dans cet écran ; les clés USB ne marchent plus et aucun nouveau périphérique (clavier piégé, clé) n'est accepté ; Internet peut être coupé. Même après un redémarrage, le verrouillage reste.

Pour déverrouiller : devant le PC, appuie sur Ctrl+R pour faire apparaître la saisie, puis tape ton mot de passe de protection CoreGuard (le raccourci seul ne déverrouille pas). Après 5 erreurs, il faut attendre 5 minutes. Tout est remis exactement comme avant.

En termes informatiques

  • Service (SYSTEM) : USBSTOR\Start = 4, stratégie DeviceInstall\Restrictions\DenyUnspecified = 1, kill switch pare-feu optionnel ; valeurs d'origine sauvegardées avant modification et restaurées au déverrouillage ; état persisté et ré-appliqué au démarrage.
  • UI : LockWorkStation, fenêtre topmost sur l'écran virtuel (réactivée toutes les 0,7 s), hook WH_KEYBOARD_LL (Win, Alt+Tab, Alt+F4, Ctrl+Échap, et toute frappe hors de la fenêtre), DACL du processus durcie.
  • À distance : watcher + scrutation 30 s d'un dossier synchronisé ; contenu comparé à une empreinte PBKDF2 en temps constant ; aucun port ouvert, aucun serveur CoreGuard.
  • Déverrouillage : défi-réponse HMAC (même authentificateur que l'arrêt du service).
  • Limite : Ctrl+Alt+Suppr n'est interceptable par aucun logiciel ; une déconnexion de session ferme l'écran jusqu'au prochain lancement de l'UI (USB et réseau restent bloqués).

6. L'intelligence artificielle : à quel niveau on est

Principe de conception : l'IA explique, elle ne décide pas. Un modèle de langage peut être trompé par le contenu même du fichier qu'il lit (injection de prompt). Les décisions de blocage restent donc à des règles déterministes, testées et vérifiables.

Comment le LLM est utilisé, pas à pas

  1. Les moteurs locaux rendent leur verdict. Si c'est « Sain », l'IA n'est même pas appelée (économie de temps et d'énergie).
  2. Sinon, CoreGuard construit un rapport technique : nom du fichier nettoyé (caractères de contrôle retirés, 200 caractères au plus), extension, taille, SHA-256, score et liste des indices.
  3. Un prompt système précise que ces données ne sont pas fiables et qu'il ne faut jamais suivre une instruction qui s'y trouverait. Il impose aussi la réponse : uniquement un objet JSON {verdict, confidence, family, explanation}.
  4. Le modèle répond en local, avec une température de 0,2 (réponses stables), 512 jetons au plus, un contexte de 4 096 jetons et un délai de 90 s. Au plus 5 appels par analyse de dossier.
  5. La réponse est analysée défensivement (AiResponseParser) : un JSON invalide est ignoré. Si le modèle est absent ou trop lent, CoreGuard produit une explication à partir des indices locaux.
  6. L'explication s'affiche dans le détail du résultat. Le verdict affiché reste celui des moteurs.

En français facile

L'IA est comme un collègue expert à qui l'on montre le rapport d'enquête, et qui le résume en une phrase claire. Elle ne voit pas le fichier lui-même, seulement le rapport, et elle n'a pas le droit de décider de la sanction.

En termes informatiques

Interface IAiProvider.CompleteAsync(system, user, ct), implémentée par LLamaSharpProvider (chargement paresseux du modèle au premier appel). Elle est injectée par DI dans ScanService, ce qui permet d'en changer sans toucher au pipeline.

8. Comment tout cela sera démontré

Chaque scénario utilise un spécimen inoffensif (dossier demo/). Il ne chiffre, ne vole et n'envoie rien. Il reproduit seulement le comportement d'une attaque pour déclencher CoreGuard, avec un nettoyage et un arrêt d'urgence.

Prérequis : installer le service dans une console PowerShell administrateur avec ./scripts/install-service.ps1. Ce script demande le mot de passe de protection, active l'audit NTFS et enregistre le fournisseur AMSI. Les démos se lancent ensuite depuis une session normale.

  1. Montrer le tableau de bord : modules actifs, service connecté, auto-défense active.
  2. Analyser un dossier d'échantillons (EICAR et fichiers de test) : verdicts, score, « preuve forte », explication par l'IA.

10. Limites assumées (honnêteté technique)

  • Mode utilisateur : un administrateur disposant de SeDebugPrivilege peut encore tuer le service et le watchdog en même temps ; le gestionnaire de services relance alors le service.
  • Après coup : une commande très rapide (par exemple vssadmin) peut avoir agi avant d'être arrêtée. Seul le driver pourra la bloquer en amont.
  • AMSI : fournisseur 64 bits uniquement et non signé ; selon la configuration, Windows peut ignorer un fournisseur non signé.
  • Leurres : un utilisateur qui ouvre et enregistre lui-même un leurre verra son éditeur arrêté. Ils sont cachés pour l'éviter.
  • BadUSB : la saisie automatique d'un gestionnaire de mots de passe peut être prise pour une injection (module désactivable).
  • IA : un LLM de 3 milliards de paramètres sur CPU est lent (plusieurs dizaines de secondes au premier appel) ; d'où le plafond d'appels et le repli local.

11. Glossaire

ETWEvent Tracing for Windows : le « journal de bord » interne de Windows, qui annonce chaque processus créé.
AMSIAntimalware Scan Interface : la porte par laquelle PowerShell et Office montrent un script à l'antivirus avant de l'exécuter.
SACL / 4663Règle d'audit posée sur un fichier ; Windows note alors (événement 4663) quel programme y a accédé.
DACLListe de qui a le droit de faire quoi sur un objet (ici : qui peut arrêter le processus CoreGuard).
HMACSignature cryptographique prouvant la connaissance d'un secret sans le révéler.
NativeAOTCompilation du C# directement en code machine : indispensable pour une DLL chargée dans d'autres programmes.
GGUF / ONNXFormats de fichiers de modèles d'IA : GGUF pour les LLM (llama.cpp), ONNX pour les modèles de classification.
CanariFichier leurre : personne ne doit y toucher, donc tout accès est suspect.
